# Erlang vs Frontend

- so Frontend has always had a top down approach, where Erlang is bottom up (perhaps also shared to Elixir)

```
asdf list-all elixir--> list all versions of a language
asdf install elixir 1.15.7 --> install a speicific version
asdf global elixir 1.15.7 --> set a global version
elixirc module_name.ex --> compile a module
```

# ASDF

- asdf is a tool for managing multiple versions of different tools (works with many programming languages)
- asdf replaces language specific package managers (e.g. nvm - Node.js, rbenv - Ruby, pyenv - Python, etc.)

```
asdf plugin add elixir
asdf plugin add nodejs
asdf plugin add ruby --> you install the core ASDF once and then add plugins for each language you want to manage
```

- generally speaking pick the latest stable version (currently 1.18.3) without any "rc" or "main" tags and match the OTP version
    - (Open Telecom Platform) is Erlang's runtime system and collection of libraries that Elixir is built on
    - OTP provides the foundation for Elixir's concurrency, fault tolerance, and distributed systems capabilities

```
asdf install elixir 1.18.3-otp-26
```

- run `erl -V` to check the Erlang version, or use the highest OTP number available for maximum compatibility

# Explain command

- `mix new protohackers --sup` --> create a new project with a supervisor, `--sup` specifically adds a supervision tree structure, which is Elixir's way of creating fault-tolerant applications that can automatically recover from crashes

note: 
- `mix` is Elixir's build tool, similar to `npm` for Node.js
- `protohackers` is the name being given to the project
- `--sup` is a flag that adds a supervisor to the project, which is a core concept in Elixir for building fault-tolerant and scalable applications

# Concept of Supervision Trees

- A supervision tree is a core concept in Erlang/Elixir's OTP (Open Telecom Platform) framework. 
- It's a hierarchical structure of processes where "supervisor" processes monitor and manage "worker" processes.
